## Intent

A **CRUD Set** is the repeatable list + dialogs pattern: one list API, optional creates, purpose patches, one content-edit patch, and optional delete. Chrome matches Users. Missing APIs omit their chrome — never stub dead buttons.

**Runtime is one component.** `CrudSet` in `shared/ui` contains the toolbar, grid or tree-grid, create dialogs, patch dialogs, delete confirm, and export dialog. Operators customize it with **props** (`spec: CrudSetSpec` plus row/data callbacks). Do not generate a parallel toolbar + grid + dialogs page.

Two entry paths share **one** `CrudSetSpec` that becomes those props:

| Path | Who | How |
|------|-----|-----|
| **Wizard** | Operator on Client Components | Catalog **Create** → **CRUD Set**. Wizard steps collect `CrudSetSpec` and **only set `CrudSet` props**. The wizard does nothing else (no extra generated chrome). |
| **Skill** | AI | Load `.claude/skills/appendo-build-crud-set` + this shard, fill `CrudSetSpec`, then render **one** `<CrudSet spec={…} />`. |

Every option in this shard is a **question** the assistant asks (or fills) so the spec is precise. The assistant **always has a suggestion** for every applicable option. Do not invent a second shape. Do not use the hidden API Connected Form / Grid / CRUD Set starters.

## Collection

**First question, always** (`CRUD_SET_FIRST_QUESTION`):

> Build with my suggestions now, and you cut later? Or do you want to decide everything now?

| Mode | What happens |
|------|----------------|
| **suggest-then-cut** | Assistant fills every applicable option with its suggestion, renders one `CrudSet`, operator cuts later. |
| **decide-now** | Assistant asks each applicable option as a question **and shows its suggestion**. Operator answers, then render one `CrudSet`. |

Do not render `CrudSet` until this fork is answered. Do not ask a blank option (no suggestion). Already-stated answers in the request skip re-asking; still apply a suggestion for everything else.

## MUST

- **Operator decides every selected piece — as questions, with a suggestion on each.** Selecting an API or chrome item is not enough. The selected-piece table below **is** the question list. Prefill every option with the assistant's suggestion. In `decide-now`, ask those questions (suggestion visible). In `suggest-then-cut`, apply the suggestions and render one `CrudSet`. Unselected pieces omit chrome — never stub dead buttons.
- Always bind a **list** API (fill, search, filter; paging when pagination is on). Operator chooses **body** (`grid` · `tree-grid` · `kanban` · `map`) and, for a grid, **pagination** on/off.
- **Every chrome piece except the list body is on/off.** The body (`columns` plus `grid` / `tree-grid` / `kanban` / `map`) is required. Filter bar, search, field filters, pagination, create, patches, delete, export, refresh, collection actions, and auto-refresh each have an explicit include. When create, export, refresh, collection, auto-refresh, and the filter bar are all off, **omit the toolbar** — do not render an empty strip above the body. Column-header sort/filter stay on the grid.
- **Grid columns** (`columns`) are required and **operator-chosen**. Each `columns[]` entry is its own object: `field` (the list-API / dataset key the cell reads — operator picks which API field feeds the column), `label` (prefill: humanize `field`), `cellKind` (`text` · `boolean-icon` · `date` · `audit` · `badge` · `chips` · `lock-status` · `link` · `image`; prefill from the field), optional `transform` (closed catalog: date-only / year / month-year / datetime / custom tokens `YYYY MM DD HH mm ss` / Yes-No / On-Off / upper / lower; prefill `date` for datetimes), optional `imageMask` (`none` · `circle`) on image cells, optional `secondaryField` + `stack` (`stacked` under, or `inline`) to show two dataset values in one column, `sortable`, `filterable`, optional `width`, optional `conditionalFormat` (closed when + `background` hex via `UiColorPicker`; first match wins; paints the cell background — never a side border; living-sample fills are pale), `cardRole` (`title` · `subtitle` · `meta` · `field` · `actions` · `hidden`; suggest first column `title`, others `field`) plus optional `cardLabel` / `cardPriority` / `phoneRole` / `tabletRole`, optional `hideBelow` (`md` · `lg`), `isRowHeader` (suggest true on the first column), **`formPlacement`** (`main` suggest · `side` — where the field sits on the Edit / View form; suggest `side` for `boolean-icon` and `lock-status`), **`formControl`** (`auto` suggest · `text` · `textarea` · `checkbox` · `chips` · `select` · `password` · `image` · `color` · `html` · `json`), optional **`visibleWhen`** (`field` + `equals` — hide the form field unless that sibling equals the text), `resizable` (default on), and when `grid.enableColumnLayout` is on: `hideable` / `reorderable` / `pinned`. Array order is left-to-right. At least one. Do not dump every response field. The actions column is **not** in `columns` — it is appended last unless a patch sets `openFromColumnId` (that id must be one of `columns[].id` or `field`). The wizard and Base Components Columns list show only the column **name** (plus reorder/remove); **Edit** opens `CreateEditModalShell` with `CrudSetColumnPropertyFields` (includes Form placement).
- If any **form patch** or **delete** exists, bind a **read-one** API that returns the minimum fields the dialog needs. Boolean-toggle patches do not require read-one.
- Every **form patch** (content, or purpose that is not a boolean toggle): read-one → dialog form showing the record → operator edits **only** fields that patch accepts → footer confirm → refresh the list.
- **Boolean-toggle patch** (purpose only, `acceptedFields` is exactly one boolean): no read-one form. Click inverts the value from the **list row** and PATCHes that field. The operator chooses `toggleConfirm`: `false` (prefill) applies on click; `true` shows `ConfirmDialogShell` first (list-row identity + next value), then PATCHes. Then refresh the list.
- **Delete**: operator chooses whether to include it. Behavior is locked: read-one → dialog **displays** the record (not an edit form) → rose confirm sends **PK** (plus change-reason body when that delete API’s Ask is on) → refresh the list.
- **Create** count: `0` omit create chrome · `1` icon-only **`ToolbarCreateControl`** Plus · `2+` same control as a **Plus dropdown** (menu item labels come from each create API — e.g. Individual / Company). `createLayout` (`split` · `adjacent`) remains in spec for designer/wizard parity but runtime chrome is always **`ToolbarCreateControl`**. A create with `steps` (≥2) opens `StepWizardShell` instead of a single form. For **each** selected create API the operator chooses `label`, optional `purpose`, and `acceptedFields` (dialog fields — do not dump every create-API field).
- Toolbar: **filters left**, **actions right** (`PAGE_TOOLBAR_*`). Left cluster is the **filter bar**: operator-chosen `filterBar.enabled` (default on; `false` hides the whole left cluster), then `filterBar.search` (default on → `ToolbarSearchInput`) plus `filterBar.searchClear` (default on) plus 0..n field filters (`checkbox-group` / `radio-group` / `select`, Users gold), then **`filterBar.listWhereFilter`** (default on → `ListFilterToolbarControl` at the **end** of the left cluster with `separatorBefore` when search or any field filter is shown). Each field filter has its own `field`, `label`, `controlType`, `options`, optional `optionsFrom` (`static` suggest · `distinct-rows` fills from the current list), and (checkbox) `matchLogic`. Do not dump every column into the filter bar. List Filter uses `useListFilter` + `ListFilterSummaryBand` header 2 + client row filter or API `where` per binding — see [`ui-toolbar.md`](./ui-toolbar.md). Column-header sort/filter stays on the grid. Actions order: Create (or Create dropdown / adjacent buttons) → collection actions → Export (unless `export.enabled: false`) → Auto-refresh checkbox (when `autoRefresh.enabled`) → Refresh (unless `refresh: false`) rightmost — **never** put List Filter in actions. Omit the whole toolbar when the left cluster is empty **and** create, export, collection, auto-refresh, and refresh are all off (`listWhereFilter` alone still shows the filters cluster).
- **Export** is an operator on/off (prefill on). It never downloads on the toolbar click. It opens a **`2xl`** `CreateEditModalShell` (locked — not `dialogs.formSize`), then downloads on confirm:
  1. **Column chips** (body) — wrap of `AppSelectionToggle` chips only (no `FormSection`); same set and order as the grid; not the actions column. Default: all selected. **Selected** = mild emerald + `Check`; **unselected** = slate + `X` — locked for every include/exclude wrap in the app ([`ui-toolbar.md`](./ui-toolbar.md) §Selection toggles).
  2. **File name** + format switch live in **header band 2** (`subtitle`): `UiInput` stem prefilled from `crudSetSuggestedExportFilename` (list `name` + date), extension **locked** to the chosen format (`.xlsx` or `.csv`) shown read-only next to the input; vertical separator then `UiSegmentedControl` (no separate “Format” label). Strip any extension the operator types; always append the locked suffix. **Both** Excel (`xlsx`) and CSV are offered (suggestion: both). Dialog default is Excel when Excel is included. Shell is **fixed `500px` tall** (`2xl` width); only the body column chips scroll.
  3. **Include header** lives in **header band 3** (`metaBand`) as a single `UiCheckbox` (no duplicate band label). Default yes.
  `xlsx` is a real workbook built on the server with **ExcelJS**. CSV is also built on the server. No current-page / record-limit picker: always export the **full queried set** (same filters/sort/search as the list), even when the grid page shows fewer rows (e.g. 325 matches, 20 on screen → 325 in the file).
- Body: `grid` (`AppTableGrid`), `tree-grid` ([`crud-pages.md`](./crud-pages.md) §Tree), `kanban` (`UiKanbanBoard` — columns from **`kanban.statusColumns`**; the status field is not a toolbar filter in kanban; cards from title/subtitle; **card click** opens the content-edit patch when one exists; drag PATCHes status when a patch accepts that field), or `map` (`UiMapPin` — pins from **latitude** / **longitude**, label from title). **`kanban` supports pagination** like `grid`. `tree-grid` and `map` are never paged. Later body kinds may be added to `CrudSetListBodyKind` only.
- **Kanban chrome** (`kanban`) exposes every operator-facing public `UiKanbanBoard` prop when `listBody` is `kanban`: `statusField` / **`statusColumns`** / `titleField` / `descriptionField` (suggest `status` / Open·Approved·… from the former status filter / `title` / `subtitle`), `height` (`full` suggest · `auto`), `columnWidth` (`sm` · `md` suggest · `lg`), `columnLayout` (`fill` suggest · `scroll` — stretch columns across the board width), `density` (`comfortable` suggest · `compact`), `showCardCount` / `showDescriptions` (suggest on), `coloredColumns` (suggest on — cycle semantic tones per status column) or single `tone` when off, `hideEmptyColumns` (suggest off), `interactive` (suggest on), `enableKeyboardMove` when interactive (suggest on), and `wipLimit` per column (`0` = off). Do not expose `className` or ReactNode slots.
- **Pagination** (`pagination`) is a spec option, collected whenever body is `grid` or `kanban`:
  - `grid` or `kanban` default **on** (`pagination !== false`): `GridPagingFooter`. Operator then chooses footer chrome (`paging`): pattern `numbered` (suggest) or `prev-next`; default page size (suggest `50`); which sizes from the closed catalog `50 / 100 / 500 / 1000 / 10000` (suggest all; cannot drop the last one); showing-range summary (suggest on); First/Last buttons (suggest on, numbered only); Paging/Infinite switch (suggest on) and default list mode (suggest paging).
  - `grid` or `kanban` **off**: omit `GridPagingFooter`. The body shows the **full queried set** in one scroll. Kanban still buckets the visible records into status columns.
  - `tree-grid` and `map`: never paged. Ignore `pagination: true` and `paging` if set. Do not offer the pagination control.
- **Sorting** (`sorting`) is a spec option. Footer sort field + direction show when pagination is on and `sorting.footer !== false` (suggest on — ui-grid: a paging footer includes footer sort). Operator chooses default field (suggest first sortable column) and default direction (suggest `asc`). Those defaults apply even when the footer is off. Column-header sort still follows `columns[].sortable`. Do not put list sort in the toolbar.
- **Grid chrome** (`grid`) exposes every operator-facing public `AppTableGrid` prop: `chrome` (`classic` suggest / `hero` — hero also paints `GridPagingFooter` as `hero`), `density` (`default` → `sm` / `compact` → `xs`), `fillHeight` (suggest on), `stickyHeader` (suggest on), `presentation` (`table` · `auto` suggest · `cards` · `table-scroll`; tree-grid omits `table-scroll`), `cardBelow` when `presentation` is `auto` (suggest `tablet`), standard card layout only (see ui-grid — `cellKind: image` columns map to card role `media`), `selection` (`none` suggest · `single` · `multiple`; keys stay on the runtime), empty/loading messages, `ariaLabel` (default list `name`), `margin` / `borderWidth` (suggest 0), `enableColumnLayout` / `showColumnLayoutControl` (suggest off — hide/reorder/pin; column resize stays on by default), and `compact` phone/tablet policy (inherit = AppTableGrid defaults; tree-grid omits freeze-first and cards-per-row). Do not expose `className`, live query state, or ReactNode slots.
- **Row actions** (`actions`): `AppGridRowActions` `maxVisible` `1..5` (suggest 3) and `align` (`start` · `end` suggest · `center`). Extra `rowActions[]` are host callbacks (`onHostAction`: `host` / `confirm`) or a view dialog (`interaction: 'view'`). Optional `disabledWhen` on patches, extra row actions, and `deleteDisabledWhen` (`has-children` · `row-is-self` · field rules). Domain modals stay on the host page — do not fold Users/Roles chrome into `shared/ui`.
- **Collection actions** (`collectionActions[]`): toolbar buttons on the queried set (Clear all). Optional confirm. The host implements `onCollectionAction`.
- **Auto-refresh** (`autoRefresh`): optional checkbox next to Refresh (suggest off). Seconds default 5. Requires Refresh on.
- **Dialogs** (`dialogs`): `CreateEditModalShell` `formSize` `sm` · `md` · `lg` suggest · `xl` · `2xl` · `3xl` · `4xl` · `maximized` · `full` for create and form patch. **More than four fields auto-widen to `4xl`** unless the operator locked `maximized` or `full`. **Export is locked `2xl`**. `ConfirmDialogShell` `confirmSize` `sm` suggest · `md` · `lg` for delete and toggle-confirm; shared `showCloseButton` / `closeOnEscape` (suggest on), backdrop tint/blur/transparency (suggest admin `medium` / `default` / `opaque`), confirm `initialFocus` `cancel` suggest or `confirm`. **`showHeader` / `showFooter`** are the standard primary header and action footer (suggest on). **`sidePanelTitle`** is the Edit / View side-column heading (suggest `Flags`). **`sidePanelPlacement`** is `right` · `left` · `end` (opposite to theme direction, suggest) · `start` (same as theme direction). **`sidePanelPinnable`** (suggest off) adds a pin control to collapse the side panel. **`sidePanelSplitter`** (suggest on) is a **ghost** drag splitter (`appearance="ghost"` — hit target only, no painted rail). **`sidePanelShowTitle`** (suggest on) and **`sidePanelTitleInHeader`** (suggest off — in-body heading) control the side-panel title chrome. **`createComponent` / `editComponent` / `viewComponent`** are optional Client Components **names** of a designed Edit / View (`heroui.record-form` / `RecordForm`). Empty generates the form from `columns` + `formPlacement`. Patches use the Edit form. **`viewKind`** (`record-form` suggest · `json` · `thread`) is the view-dialog body. View is read-only with no submit. Delete tone stays locked `danger`. Do not expose `contained` or className slots.
- Create / form-patch / view / delete-display bodies are **`RecordForm`** (living sample: Base Components → **Edit / View**). Layout is a main field grid plus an optional **docked** side panel for `formPlacement: 'side'` fields (checkboxes, lock status). The rail is flush to the dialog header, footer, and edge (`border-s` / `border-e`, no inset rounded card). It **shares** the inspector **wash** (`--app-inspector-rail-bg`) and **ghost splitter** ([`ui-inspector-rail.md`](./ui-inspector-rail.md)) — not boxed KV cards. The main column keeps equal **15px** padding on left and right. Default placement is **`end`** (opposite the theme direction). Operator can pin the panel, turn the ghost splitter off, hide the title, put the title in a side-panel header band, and set the side-panel fill from the **current theme** (inspector wash) or a **specific hex**. **RecordForm** honors `formControl` and `visibleWhen`. Do **not** wrap each field in a second `FormSection` with the same title as the field label. **Hand-written CRUD create/edit/view dialogs** (Roles, Base Info, Org/Geo) render the same `RecordForm` — do not fork a parallel field layout. **Configurators** (wizard, living sample property panels) use **`CrudSetConfigCheckbox`** as a **yes/no `UiSelect`** with a short `FormField` label. **RecordForm** booleans pass `control="checkbox"` (checkbox + label on one row; RTL reverses). Do **not** wrap a checkbox in `FormField` (label-over-input) and do **not** repeat the same words on both `FormField label` and checkbox children. **History** (when the bound model `history.enabled`): Edit/View follow [`record-event-log.md`](./record-event-log.md) form surfaces — list-row History opens the grid; Edit/View `headerExtra` only toggles field History icons (off until pressed). Create omits history. Named-API change reason uses a Confirm overlay on form-patch Save, toggle, kanban move, and delete when that write API’s Ask is on (optional or required) — never on create. Omitted `changeReasonPolicy` defaults Ask `off`; the living sample hydrates from `PATCH /api/sample-mock/records/:id`. Do not map `viewKind: thread` to the event Timeline.
- Patch / delete row actions live in the **last** column unless a patch sets `openFromColumnId`. **Content-edit** defaults to opening from the first display column (`title`, `name`, …) or row `id`, else the first column — not from actions. Set `openFromColumnId` to `actions` to keep content-edit in the actions cell, or to a column id / `field` to pin a specific column.
- Dialogs: `CreateEditModalShell` for create, **form** patches, and **export options**; `ConfirmDialogShell` `tone="danger"` for delete; `ConfirmDialogShell` (default tone) when a boolean-toggle has `toggleConfirm: true`. Operator chooses the public dialog chrome in `dialogs`. Base Components controls only. Every generated field has `label` + `hint`.
- After a successful create / patch / delete: close the dialog, toast, refresh the list (and any same-source regions). After export: close the dialog, download, toast (no list refresh).

## NEVER

- Dump every API field into columns / the filter bar / create / patch because the field exists, skip the first collection-mode question, or ask an option with no suggestion.
- Duplicate a section title as the only field label inside it (use Include / Body / Preset, not a second “Filter bar” / “Columns” field).
- Wrap each record field in a second `FormSection` with the same title as the field, stack a checkbox under a `FormField` label, or put the same words on both `FormField label` and checkbox children.
- Invent a second Edit / View runtime beside `RecordForm`. CRUD Set dialogs either generate `RecordForm` from columns or point at a designed Edit / View by **component name**.
- Invent a formula language for column display — use the closed `transform` / `stack` / `conditionalFormat` catalogs.
- Show Create, Export, Refresh, patch, or Delete chrome when the matching API / include flag says omit.
- Leave Refresh always-on, or render an empty toolbar when filter bar, create, export, collection, auto-refresh, and refresh are all off.
- Omit the list body or treat `columns` as optional chrome — a body is required (`grid` · `tree-grid` · `kanban` · `map`).
- Download Excel/CSV from the toolbar without the export-options dialog.
- Offer PDF (or any format besides `xlsx` / `csv`) in a CRUD Set export dialog.
- Show `GridPagingFooter` when `pagination` is off, or paginate a `tree-grid` or `map`.
- Invent a second paging footer, or offer cursor / load-more / page-jump as CRUD Set paging patterns — use `numbered` or `prev-next` on `GridPagingFooter`.
- Put list sort in the toolbar. Footer sort belongs on `GridPagingFooter` when pagination is on.
- Leave AppTableGrid / AppGridRowActions / CreateEditModalShell / ConfirmDialogShell / ToolbarSearchInput public props hardcoded — they belong on `CrudSetSpec.grid` / `actions` / `dialogs` / `filterBar.searchClear` / `columns[]`.
- Expose `className`, live query/selection keys, `contained`, or ReactNode slots on the spec.
- Offer current-page / all-pages / record-limit row scope — export is always the full queried set.
- Let the operator change the file extension; only the stem is editable.
- Let a patch dialog edit fields the patch endpoint does not accept.
- Skip read-one for a **form** patch or delete (do not trust the list row as that dialog’s source of truth). Boolean-toggle is the exception: it **must** use the list-row boolean.
- Use `boolean-toggle` on a content patch, on more than one field, or on a non-boolean field.
- Navigate to a separate create/edit **page** for these dialogs (Users-style in-app modals). Deep-linked record editors are out of scope for a CRUD Set.
- Duplicate this contract in the wizard — wizard fields **are** `CrudSetSpec` written onto `CrudSet` props.
- Generate a second toolbar + grid + dialogs page beside `CrudSet`. The wizard does not create extra chrome.

## API roles

| Role | Cardinality | UI if present |
|------|-------------|----------------|
| **List** | 1, required | Toolbar filters + body when those pieces are on. Paging footer on grid when `pagination` is on (`paging` chrome). Columns = `columns` (order = array order). Body is always shown. |
| **Read-one** | 1, required iff a form patch or delete | Feeds form-patch and delete dialogs. Not used for boolean-toggle. |
| **Create** | 0..n | Toolbar create / dropdown. Operator chooses include, then label + `acceptedFields` per create. |
| **Content patch** | 0..1 | Dialog that patches fields that **hold** the record (`interaction: form`) |
| **Purpose patch** | 0..n | Small targeted updates. Default `form`. If exactly one boolean field: `boolean-toggle` (click; optional confirm). |
| **Delete** | 0..1 | Rose confirm; body = PK |
| **Export** | 0..1 (default on) | Toolbar button → options dialog → server `xlsx` (ExcelJS) or `csv` of the full queried set |
| **Refresh** | 0..1 (default on) | `ToolbarRefreshButton` rightmost. Off omits it. |

## Do this

1. Ask `CRUD_SET_FIRST_QUESTION`. Then fill `CrudSetSpec` (`crudSetSpec.ts`): **suggest-then-cut** applies a suggestion on every applicable question and renders one `CrudSet`; **decide-now** asks those questions with the suggestion shown. List API, columns, body, and grid chrome always apply.
