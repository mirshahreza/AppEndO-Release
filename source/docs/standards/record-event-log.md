# Record Event Log

Audience: **AI agents**. Load this shard when the task touches record history, timeline, client metadata on writes, Users/Profile audit, auditee, DSAR/hold, or `base_record_events`.

Canonical implementation: `src/server/domain/record-events/` · `src/server/domain/client-context/` · `GET /api/record-events`.

Wave 4 (SIEM CloudEvents, time-travel as-of, bulk collapse, track-budget warning, `trackReads` / `history.viewed` emit) is **schema/docs only** — do not code until Users is closed. Offload of hot logs / record events is **this** surface (Settings → Logs → Retention), not Wave 4.

## MUST

- **Default for record-scoped audit and change tracking:** when the need is «what happened to this record» (field/status/association changes, domain actions anchored on a `subject_kind` + `subject_id`, Timeline / History UI, auditee, change reason, client metadata on writes), use **`base_record_events`** (`emitRecordEvent`, Data API / `PLATFORM_HISTORY_MARKS`, package payload patterns such as `hwyDossierKind`) — **do not** add per-entity `*_history`, `*_change_log`, `*_audit`, or parallel tracking tables. Extend closed or documented `event_kind` + `payload` when the domain action does not map to `field.changed` / `association.*` alone. Legacy side tables are migrate-in / read-union only until ETL completes; greenfield work does not create new ones. **Exceptions (stay separate tables):** HTTP app logs (`base_logs_app`), auth audit (`base_logs_auth_audit`), and other non–record-subject telemetry or ledgers named in their own shards (e.g. message dispatch) — not record history.
- Append-only history of **what happened to a record**. The current row stays source of truth. Do not rebuild the row from events (no event sourcing / replay).
- One Sequelize control-plane table `base_record_events` plus `base_record_event_holds`. Prisma is locked — no new Prisma models.
- Writers (`source`, not `event_kind`): `patch` · `workflow` · `status-log`. `status-log` is **reserved** for a dedicated status writer; Data API lifecycle-field writes emit `status.changed` with `source=patch` or `source=workflow`.
- Closed `event_kind`: `created` · `deleted` · `field.changed` · `status.changed` · `association.added` · `association.removed` · `access.denied` · `config.changed` · `history.erased` · `history.archived`.
- Track definition lives in **studio-meta** (`history` on model / column / association): Track / Redact / lifecycle / legalHold only. Retention age is Settings → Logs, not per model. No Reason on column or association History.
- Reason (`reason_code` / `reason_text`) lives on the **event**, never as a domain column. Ask / capture / vocab live on **each named API**: Data API definition (`changeReason` on `EdgeApiDefinition`) or built-in/managed function (`metadataJson.changeReason`). Not on column History and not as a global “any PATCH”. Until a function stores its own policy, Express Users / sample-mock fall back to code constants (`USERS_PROFILE_CHANGE_REASON`, lock, roles). Stored `{ reasonAsk: 'off' }` wins over those constants. Track and reason run **in parallel**: a tracked field always emits if it changed; Confirm follows that API’s Ask. **Do not** put Reason settings on GET/list/getOne, collection create (POST), password, or auth. Runtime never asks on those operations; `assertChangeReason` runs only on update / patch / delete (and resource actions such as lock/roles). One write of that API = one `correlation_id` = **one** reason. Do not collect per-field reasons.
- Transport: headers `X-AppEndO-Change-Reason-Code` / `X-AppEndO-Change-Reason-Text`, or body `__changeReason*` / `__client` stripped before write. Header wins over body. Restore extras: `__revertedFromSeq` / `__revertedFromEventId` → event `payload.revertedFromSeq`.
- Client metadata: closed catalog, per-operation `clientContext.fields[]` `off|record|require`. Stored as `client_json` `{ observed, claimed }`. Envelope `X-AppEndO-Client` or `__client` (header wins). 4KB cap. Claimed IP is discarded. `observed.ip` = `req.ip` only.
- Require applies to **write** operations only (never GET/list). Do not bypass Require with User-Agent. Default identity profile is **Record not Require**. Location is never globally required; prompt `getCurrentPosition` only on Save via `attachClientContext` (never on `apiFetch`). `apiFetch` attaches identity only (`attachIdentityClientHeader`). Hosts that set location Require must call `attachClientContext` on Save; Users v1 does not.
- Interceptor is `apiFetch` in `src/shared/api/authSession.ts`. Install ID is not a JWT — cookie/`localStorage` key `appendo_install_id` is allowed.
- `correlation_id` = one save. `request_id` = one HTTP (`x-request-id`). Logs `correlationId` is the HTTP id.
- Successful events share the domain write transaction **only when the model Sequelize is the control-plane instance**. Edge-DB writes emit post-commit on the control plane (cross-DB transactions are not used). Prisma Users / Profile: emit after Prisma success.
- `actor_user_id` = `req.impersonatorId ?? session user`. `acting_as_user_id` = session user when impersonating. `actor_kind`: `user|workflow|agent|system|impersonation`. Do not swap JWT without keeping impersonator. History and auditee **Actor** / **Reason** cells show **read-time** identity (display name; `username · #id`) and reason **title** (plus `reason_text`). Names are not stored on the event. Bare actor id or vocab code alone is not enough.
- Redact `from_value`/`to_value` with p-118 `encryptCredential` (`enc:v1:` + blob). **v1 never unmasks** (even ADMIN). There is no Unmask grant yet — do not add a decrypt API unless a later plan names it.
- Idempotent emit: unique `idempotency_key`. Default key = `` `${requestId|noreq}:${correlationId}:${eventKind}:${field|-}` `` (max 128). Retry / unique-race returns the existing row.
- Restore previous value = a **new PATCH/PUT** with `payload.revertedFromSeq` — not replay. Reason `100.6.8`. Users restore supports profile fields, `locked`, and `email`. `username` / `mobile` are tracked but **not restorable** until `updateUser` writes those columns.
- Timeline on the auditee page may jump to Logs by `request_id` (`/studio/logs?requestId=`). Search hot `base_logs_app` first; if that family’s Keep destination is **same-type-db**, search that archive next. Missing in both (or dest is JSON files / dest down) → English **Log expired**. Do not search JSON files. The subject History dialog has no Logs action. Sign-in/lock on a person History list is a **read-time union** from `base_logs_auth_audit` (`includeAuth=1`, `projection: 'auth'`, synthetic kinds such as `auth.login`) — never insert login into events. Auth projections have `requestId: null`.
- Clock skew `|clientOccurredAt − occurred_at| > 5 minutes` stores `observed.clockSkewMinutes` and a Timeline badge; do not reject the write.
- Retention **policy** lives in Settings → Logs → **Retention** (not list toolbars). **App logs / Auth audit** and **Record events** share one **Older than** combo and one destination picker (same day options — not per-model `history.retentionDays`). Settings does not list those family names as extra rows. There is no Discard vs Keep a copy: after the age, matching hot rows are always copied to the destination and then removed from the operational database. Destination options: same-type connections (separate DB, same install dialect, vault connection, purpose `log-archive`) plus **File** last (default — gzip JSONL per job run). Not a sidecar `*_archive` table on the operational control plane. Not Edge/tenant. Not Prisma. Copy fail = hot untouched. Auth audit `discard` → 400. Hold rows and `history.legalHold` skip policy **and** Clear. After **offload** of events, emit hot stub `history.archived` with payload `{ fromSeq, toSeq, offloadMode, archivedAt }` (Timeline says Archived, not Erased). Jobs: `log_retention` (app logs + auth audit) and `record_event_retention` (`record_event_purge` aliases the events executor). Dry-run / Run now / Clear are **operations** inside **Control logs** (Logs, `scope: logs`) and **Control records** (Record Events, `scope: recordEvents`) — auto-size `RetentionControlDialog`, confirm with **Start**, then progress and a result; **Done** returns to the list. Settings does not run them. Test archive connectivity on the destination connection, not Settings. **No boot cron**. Studio Jobs is the queue only. Include archived (ADMIN, short timeout) only when dest is same-type-db; dest down → toast **Archive unavailable**. JSON dest is not searchable in Studio. Clear on Logs / Record Events wipes **hot** only.
- First consumer is Express `/api/users` + `/api/profile` (including self-service account / editable profile fields) + `UserFormModal`, driven by `PLATFORM_HISTORY_MARKS`. One Timeline on the person (`subject_kind=base_users`). Junction tables do not get `history.enabled`. Attach marks **empty-only** (operator studio-meta edits win, same as Story).
- Hawiety member dossier (`subject_kind=hwy_members`, `PLATFORM_HISTORY_MARKS`) tracks editable dossier fields from `PATCH /api/hwy/member-directory/:id` (`field.changed` / `membership_status_code` as lifecycle). **Redact** `phone1`, `phone2`, and `email`. Legacy `HWY_Members_ChangeHistory` ETL imports into the same table (`idempotency_key` prefix `hwy-etl:ch:`); member dossier change log merges `hwy_members` events with `base_users` when linked.

## MUST NOT

- Event sourcing, per-entity `*_history` / `*_change_log` / dedicated audit tables for record tracking (use `base_record_events` instead when the pattern fits), merging log tables, sidecar `*_archive` tables on the operational control plane, 20-field hard cap, global GET logging.
- Track `password_hash`, IMEI/IDFA/GAID/serial/MAC, cookies, tokens.
- Writable events API; WORM/Merkle; identity-level impersonation that drops the operator.
- Wave 4 emit (`trackReads` / `history.viewed`) even if studio-meta flags are true.
- GPS Require on generic CRUD; location prompt on list/GET/`apiFetch`.
- Overwrite operator studio-meta history edits on re-seed (empty-only attach, same as Story).
- Put change-reason vocab back at `100.4` or `100.5`.
- History icon or Timeline on Create, list toolbar, Data Studio modeler, create wizard, or Studio shell header. Edit/View `headerExtra` does not open the History dialog.
- Replace inspector Created/Edited stamps with event timestamps.
- Per-chip History on association chips (icon stays on the field label).
- Convert CRUD Set `viewKind: thread` into the record-event Timeline.
- Embed record-event payload, provenance lines, Timeline, Devices, or a History accordion inside domain forms unless the operator names that surface.
- Show a reason Confirm when that API’s Ask is off, or when the form has nothing to save.
- Put Reason / Vocab / Manage reasons on column or association History (those stay Track / Redact). Do not add a Record Events nav item or a new reason table.
- Put record-event retention days on model History. Age is Settings → Logs only, same pattern as app logs.
- Collect a separate reason per field on one save (one save = one reason).
- Paint only `actorUserId` or `reasonCode` in History / auditee Actor / Reason columns.
