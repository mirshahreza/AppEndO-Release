# Component Designer — Refactor Spec Package

این پکیج قبلاً شامل چند نسل از اسناد برنامه‌ریزی/ممیزی بود (Tier 1، Tier 2، گزارش‌های Production Readiness، لاگ‌های ممیزی خوشه‌ای Claude Code). همه‌ی آن مسیرها **اجرا و تمام شده‌اند** و مستقیماً در دو سند فعلی زیر جذب/جایگزین شده‌اند؛ برای جلوگیری از سردرگمی بین نسخه‌های قدیمی و وضعیت واقعی فعلی کد، حذف شدند (در تاریخچه‌ی git همچنان قابل‌بازیابی‌اند).

## اسناد زنده (تنها مرجع فعلی)

- **`20-DESIGNER-ELEMENT-PARITY-AUDIT.md`** — ممیزی کامل و به‌روز پاریتی Canvas/Preview/Export برای تک‌تک المنت‌های Component Designer. شامل دو دور ممیزی کامل (۲۸ مورد دور اول + ۷۱ مورد دور دوم) + یک بازبینی مستقل تأییدی + بخش «گواهی آمادگی Production» + بخش «قابلیت‌های تصمیم‌گرفته‌شده‌ی بعدی» (Hydration محتوا، اکشن Navigate، اتصال ۴۰۴/error) + بخش ۱۹ (باگ گزارش‌شده‌ی کاربر — آدرس API در ویزاردهای from-API).
- **`client-components-gap-analysis-fa.md`** — تحلیل شکاف سطح پلتفرم Client Components نسبت به App Builder/Form Builder/Dashboard Builder های معتبر صنعت (Retool/Bubble/Webflow/…)؛ نسخه ۴ شامل یک بازبینی کامل با کد واقعی (بخش ۲۰) + تحلیل عمیق پاریتی صفحه Users.
- **`client-components-per-element-gap-analysis-fa.md`** — مکمل سند بالا: تحلیل element-by-element هر ۱۲۳ المنت Toolbox؛ نسخه ۲ شامل بازبینی کامل با کد واقعی.
- **`21-DESIGNER-BUGFIX-EXECUTION-PHASES.md`** — نقشه‌ی اجرای فازبندی‌شده و مهندسی‌شده‌ی هر باگ/قابلیت اسناد بالا (۵۷ فاز؛ فازهای ۱-۲۳: ممیزی پاریتی + قابلیت‌های جدید اولیه؛ فازهای ۲۴-۵۷ «بخش سوم»: پاریتی کامل صفحه Users + گپ‌های تأییدشده‌ی دو سند Gap Analysis)، هرکدام مستقل و قابل‌اجرا در یک چت جدید، با پروتکل تأیید مشترک.
- **`19-REUSABLE-COMPONENT-RESOLUTION-ENGINE.md`** — تنها سند طراحی/پلن قدیمی که هنوز **باز و مرتبط** است؛ سند ۲۰ هنوز به آن به‌عنوان یک شکاف معماری شناخته‌شده (`reusable.component.*`) ارجاع می‌دهد.
- **`catalog-maturity-report.json`** — خروجی تولیدشده‌ی زنده (نه یک سند دستی)؛ توسط ابزار/تست‌های پروژه بازتولید می‌شود.

## چطور با این پکیج کار کنیم

1. برای فهمیدن وضعیت فعلی هر المنت (چی درست است، چی رفع شده، چی هنوز مانده) → `20-DESIGNER-ELEMENT-PARITY-AUDIT.md`.
2. برای فهمیدن شکاف‌های سطح پلتفرم/element نسبت به صنعت و پاریتی صفحه Users → `client-components-gap-analysis-fa.md` + `client-components-per-element-gap-analysis-fa.md`.
3. برای اجرای یک فاز رفع باگ/قابلیت جدید → کل `21-DESIGNER-BUGFIX-EXECUTION-PHASES.md` را به یک Agent در یک چت جدید بده و بگو کدام فاز را اجرا کند.
4. برای تصمیم درباره‌ی «کامپوننت قابل‌استفاده‌ی مجدد» → `19-REUSABLE-COMPONENT-RESOLUTION-ENGINE.md`.

## چرا اسناد قدیمی حذف شدند

نسل‌های قبلی این پکیج (Tier 1: اسناد `10`-`15` + `TIER1-BASELINE-REPORT.md`؛ Tier 2: اسناد `00`-`09`؛ دور Production-Readiness: اسناد `16`-`18` + `CLAUDE-FULL-AUDIT-LOG*.md` + `BINDING-PARITY-FINDINGS.md` + `FINAL-COMPLETION-REPORT.md`؛ پوشه‌های `t1-14/17/37-validation`) هرکدام یک مرحله از تاریخچه‌ی این پروژه بودند که به‌طور کامل اجرا شد. نتیجه‌گیری‌ها و یافته‌های باقی‌مانده‌ی معتبرشان همگی در ممیزی جامع و از‌صفر سند `20` دوباره بررسی و ثبت شده‌اند — نگه‌داشتن نسخه‌های قدیمی فقط ریسک می‌کرد کسی به‌جای کد فعلی، وضعیت چند ماه قبل را مرجع بگیرد.
